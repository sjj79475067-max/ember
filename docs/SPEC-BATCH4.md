# 第四批规范：随手记（手机语音/文字 → 自动整理 → 你确认 → 落到项目）

依据：Paperless-ngx 的「收件 → 待审 → 归档」、GTD 的收集篮、飞书长连接机器人与卡片回传交互。

## 1. 流程
1. **收**：飞书私聊机器人（或群里 @）、iPhone 快捷指令、网页「随手记」输入框。语音先走语音识别。
2. **整理**：有 AI 用 AI（结构化输出：类型、项目、置信度、原话依据），没 AI 用规则（按句拆、按项目名/别名认项目、口语日期）。一句话说多件事会拆开；涉及多个项目分别归属；拿不准项目就留空（确认时进收件箱或由你选）。
3. **审**：飞书里回一张卡片，每条都有「确认 / 换项目 / 不要」，还有「全部确认」和「去网页改」。网页「随手记」页可以改类型、项目、标题、日期、在等谁。
4. **落**：确认后按类型落库：待办 → 事项；进展 → 记在已有事项上（办完就核销，在等谁就写 waiting_for）；会议 → 会议档案（只归档）；采购/合作/行程 → 事务；笔记 → 知识库。行程没出发日期时先记一条「定行程」待办。
5. **同步**：网页上处理了，飞书卡片同步变状态；卡片变绿并给「查看」链接。

没确认之前，草稿不进任何项目、不影响进度和提醒。

## 2. 安全
- 飞书只认绑定的本人：设置页生成 6 位绑定码（10 分钟有效），私聊机器人发「绑定 123456」。其他人的消息不回话、不落库；其他人点按钮无效。
- 快捷指令用单独的「随手记密钥」：只能往待审箱投，读不了数据、不能直接落库；可随时作废重换。
- 飞书 App Secret、语音识别 Key 加密存库（也可用环境变量 FEISHU_APP_ID / FEISHU_APP_SECRET）。
- 同一消息幂等：渠道 + 消息 id 去重，飞书重推不会重复生成。

## 3. 渠道层独立
`src/lib/capture/channel.ts` 定义统一信封和适配器接口（start/stop/status/sendReview/updateReview/sendText）。整理、审批、落库全在 `capture/service.ts`，与渠道无关。
- 飞书（`feishu.ts`）：官方 SDK 长连接，不需要公网地址；设置里可切 Lark（海外）。
- HTTP（`http.ts`）：`POST /api/capture`，JSON `{text, id?}` 或 multipart `file=语音`。
- 网页。
做海外版：新写一个 Slack/Telegram 适配器注册进去即可。

## 4. 语音识别（可插拔）
OpenAI 兼容 `/audio/transcriptions`。本机 SenseVoice/faster-whisper 服务或云服务（硅基流动等），设置页填地址/模型/Key 并可测试。没配置时语音消息提示改发文字。

## 5. 其他
- 飞书里发「今天」：回今日安排（三件事、今天做什么、该催的、要拍板的数量）。
- 「今日 → 需要你拍板」里出现「随手记待确认」；侧栏「随手记」显示待确认数；快捷指令投递后按通知设置推送一条提醒。
- 开发实例默认不连飞书（必须在设置里启用）；同一个机器人只让正式实例连，否则消息会被随机分走。
