# 对标自检：Ember vs 开源方案

> 方法：逐项对照"单人、自托管、Agent 优先、免费"的目标场景，用真实开源项目的定位与已知弱点做比较（依据：各项目 README/文档与常见用户反馈）。结论分为 **更好 / 持平 / 更差（已处理或接受）**。

## 1. 任务与项目管理

| 对比项 | Plane | Vikunja | Focalboard | 本系统（Ember） | 结论 |
|---|---|---|---|---|---|
| 人类 UI 完成度 | 很高 | 中 | 中 | 中上（清单/看板/命令面板） | 更差（接受：不做多人协作视觉） |
| Agent 原生调用 | 无 MCP，无机器可读能力清单 | REST API 有，但不面向 LLM | 无 | MCP + REST + llms.txt + onboard | **更好** |
| 完成质量把关 | 无 | 无 | 无 | 必须带证据 + checklist_verify | **更好** |
| 截止/阻塞提醒 | 有通知，需要本地服务 | 有 | 弱 | Reminder Inbox + 每次连接推给 agent | **更好** |
| 依赖复杂度 | 多容器 + Postgres + 对象存储 | 单二进制 | 多容器 | 单容器 + SQLite | **更好**（免费、低资源） |
| 多人实时协作 | 强 | 一般 | 一般 | 无 | 更差（不在范围） |

## 2. Agent 记忆 / 上下文工具

| 对比项 | mem0 | Letta | Basic Memory | Task Master | 本系统 |
|---|---|---|---|---|---|
| 是否依赖付费 LLM | 是（写入就要 LLM） | 是 | 否 | 是 | 仅导入时可选 |
| 存储可解释性 | 向量库 | 状态机 | Markdown 文件 | 项目内 JSON | SQLite 表 + 事件流 |
| 进度/清单闭环 | 无 | 无 | 无 | 有（但 36 工具/2 万 token） | 有（28 工具/约 5.8k token） |
| 跨会话归集 | 语义记忆 | 需常驻服务 | 手工 | 项目内 | onboard + 会话 + 认领 |
| 会议档案/资料定位 | 无 | 无 | 无 | 无 | **有** |

## 3. 会议与资料

| 场景 | 常见做法 | 本系统 |
|---|---|---|
| 飞书/腾讯会议记录 | 各平台各自保存 | 统一导入（粘贴/md/txt/docx/pdf），统一会议档案 |
| 自动生成待办 | 需要各平台 AI | 可选 AI；无 AI 时确定性规则抽取（已单测） |
| 资料归档 | 网盘/GitHub | 只登记位置（机器/路径/链接）+ 归档去向 + 核验提醒 |
| 历史对话补录 | 手工整理 | `ingest_history` 指纹去重，可安全重试 |

## 4. 已知更差项与处理

| 项 | 影响 | 处理 |
|---|---|---|
| 多人协作/权限细分 | 现在是单 owner，多账号角色仅预留 | 接受（个人创业者场景）；数据模型有 role 字段 |
| 中文全文检索 | 目前用 LIKE + 子串匹配，非分词 | 数据规模小（千级条目）时足够；后续可接 FTS5 trigram（已验证 sqlite 支持） |
| PDF 提取 | 自写轻量解析，扫描件无文本 | 已是"可选优化"：失败时提示粘贴文本；AI 多模态解析可作为后续增强 |
| 提醒的推送 | 只在 agent 连接时拉取，不会主动弹消息到手机 | 接受：Agent 连接即推送；如需手机通知，可接 ntfy/Bark（后续） |
| 大附件 | 中心不存文件 | 设计如此：由 agent 管理 + 位置登记 |
