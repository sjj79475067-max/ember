# 第三批规范：秘书层（今日 · 等待清单 · 需要你拍板 · 拖延识别 · 每周复盘 · 简报升级）

依据：GTD（Waiting For 必须带委托日期、每周复盘、Someday/Maybe）、Sunsama（每日规划、未完成自动滚动、连续滚动多天提示放弃、周复盘三步）、Motion（每日议程）、优秀行政助理的工作清单（承诺清单、等待回复、到期表、会前简报）。

目标：你不用去找事，秘书把「今天要做的、在等谁、要你拍板的、快到期的、拖着没动的」主动摆到面前；agent 连上来拿到同一份上下文。

## 1. 事项新增字段（字段名用 waitingFor，与依赖关系的 waitingOn 区分）
| 字段 | 说明 |
|---|---|
| waitingFor | 在等谁/什么（客户、平台审核、供应商、某个 agent）。非空即「等待中」 |
| delegatedAt | 什么时候交出去的（GTD：没有日期就说不出「我什么时候问的」）|
| followUpAt | 什么时候去催；默认 delegatedAt + 3 天 |
| plannedFor | 计划在哪天做（今日清单）|
| rollCount | 计划日过了没做完、自动滚到今天的次数 |
| deferUntil | 先放一放，到这天之前不出现在今日/提醒里（Someday/Maybe）|

规则：
- 设 `waitingFor` 时自动记 `delegatedAt=now`、`followUpAt=now+3天`（可改）；到 `followUpAt` 进「该催了」并提醒；对方回复后清空 `waitingFor` 或直接完成。
- 每天第一次打开（或任意工具调用触发刷新）：`plannedFor < 今天` 且未完成的自动滚到今天，`rollCount+1`；**连续滚 3 次**进「拖延」，问你：今天就做 / 改日期 / 先放一放 / 不做了。
- `deferUntil` 未到的事项不进今日、不发到期提醒（逾期提醒照发）。

## 2. 今日（/today，秘书首页）
一屏五块：
1. **今天做什么**：逾期 + 今天到期 + 今天计划的 + 自己在做的（P0 不自动进，在「加入今天」里排最前，避免被几十条模板合规项淹没）；按「逾期 → 今天到期 → 计划 → 其他」排序；可一键加入/移出今天。
2. **需要你拍板**：待批条例、待确认的需求放弃、阶段评审建议、完成待核实、阻塞项（需要谁做什么）、合作没下一步。每条一个按钮直达。
3. **在等别人**：按「该催了」优先，显示等了几天、上次什么时候问的。
4. **快到期**：未来 7 天的台账到期、采购需到货、合作下一步、行程。
5. **拖着没动**：滚动 ≥3 次或 14 天没有任何动静的未完成事项。

## 3. 每周复盘（/review）
三步（Sunsama + GTD）：
1. 回顾：本周完成（按项目）、本周新增、延期的、放弃的。
2. 清理：等待清单逐条过（还在等/催了/不等了）；拖延清单逐条决定；收件箱分拣；没有下一步的项目。
3. 定下周：写下周最重要的三件事（可从事项里选），写一句复盘。
保存为 `weekly_reviews`（周起始日、三件事、复盘、统计快照）。首页和 agent onboard 显示「本周三件事」。

## 4. 简报升级
今日简报/周报增加：今天计划、在等谁（该催的）、需要你拍板、7 天内到期的台账/合作/行程、本周三件事进度。推送渠道沿用 Bark/ntfy/Webhook。

## 5. Agent
- `checklist_update` 增加 `waiting_for` / `follow_up_at` / `planned_for` / `defer_until`。
- `today(plan_add?, plan_remove?)`：拿今日五块（与网页同一份推导），可顺便加入/移出今天。
- `weekly_review`：不带参数拿复盘素材；带 `top3` + `notes` 保存（agent 可起草，用户在网页确认后生效——保存人记为 agent 时标「草稿」）。
- onboard 增加 `today` 摘要与本周三件事；how_to_work 增加：开工先看 today，交出去的事写 waiting_for。
